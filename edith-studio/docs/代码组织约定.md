# EDITH Studio：架构与代码组织约定

> 面向开发者与 AI。新增代码前先遵守这里；没有真实复杂度，不增加抽象。

## 核心目标

- 让一次请求的路径能顺着读：HTTP 输入 → Agent Run → Framework Event → StreamEvent → SSE。
- `main` 只启动应用；Agent 内核自己拥有模型、工具、Runner 与会话等能力。
- 本地单用户客户端保持线性简单，不复制多用户服务端 EDITH 的复杂度。

## 包与目录

- 按**业务能力**分包，不按 `domain`、`infrastructure`、`common` 等技术层分包。
- 包内按**运行路径**拆文件：`service.go`、`run.go`、`stream.go`、`http.go`，不要按名词切成 `model.go`、`tool.go`。
- 类型就近放在所属能力的 `types.go`；只有已经被多个能力共用的类型才可提取。
- 禁止预建空包、`utils`、`common`、集中 `types` 包或大一统 `httpapi` 包。

```text
internal/
├─ studio/     # 本地应用与 HTTP：路由、SSE、进程级应用入口
├─ engine/     # EDITH 执行内核：Open、Run、Cancel、Runner、Event 翻译
├─ models/     # 模型配置类型与模型实例组装
├─ tools/      # Agent Tool 与 ToolSet 的统一注册
└─ session/    # SessionService 等会话持久化能力
```

- `mcp`、`permissions` 当前都不保留空包、空接口或半成品实现；出现真实需求时再增加。

## 对象、依赖与生命周期

- 默认使用函数。只有真实持有长期依赖、状态或 `Close` 责任时才创建 `Service` 等结构体。
- 长期对象统一使用 `New(Dependencies{...})`；依赖必须命名传入。
- 纯数据直接使用结构体字面量，不创建无意义的 `NewXxx`。
- 不使用 package 级可变状态保存当前请求、会话或项目。
- 谁创建资源，谁在同一可读范围内关闭；返回资源时显式返回 cleanup 或说明 Close 责任。
- 所有 channel 变量、字段和参数必须以 `Ch` 结尾，例如 `frameworkEventCh`；禁止 `events`、`output` 这类含义不明的名称。

## 装配与数据流

- `cmd/edith/main.go` 是应用轻壳：确定启动环境、启动 `studio`、监听 HTTP、处理进程退出；它不组装 Agent 内核零件。
- `studio` 只创建 `engine`，并将 `ProjectRoot` 交给它；`studio` 只认识 Engine 的 Run、Cancel 等应用能力。
- 每个能力包读取自己的配置文件，例如 `models` 只读取用户级 `models.yaml`。配置格式、读取与校验都归该能力包所有，且完整字段必须定义在该包 `types.go`。
- `engine.Open(ProjectRoot)` 在内核内组装长期不变的 Model、LLM Agent、ToolSet、SessionService 与 Runner，并持有 Runner。
- `tools` 只注册当前真实存在的 Agent 能力；目前只有 `NewToolSets`。出现独立 Tool 后再增加 `NewTools`。
- 每次 `Runner.Run` 显式传递本次事实：`ctx`、`sessionID`、消息、`requestID`、超时及必要的临时 RunOptions。

## 会话与项目隔离

- EDITH Studio 是 Coding Agent；会话默认按 `ProjectRoot` 隔离，不同项目的对话历史绝不互通。
- 框架的会话键是 `<appName, userID, sessionID>`。本地单用户场景中，`userID` 承担“项目工作区身份”，不是人类账号。

```text
appName   = edith-studio
userID    = workspace:<规范化 ProjectRoot 的稳定哈希>
sessionID = 单条对话的 UUID
```

- `ProjectRoot` 必须先转为规范化绝对路径，再计算 `WorkspaceID`；同一目录重启后必须得到同一个 `WorkspaceID`。
- `session` 使用框架 `SessionService` 的 `ListSessions`、`GetSession`、`DeleteSession` 实现侧栏、历史切换与删除；不得绕过 Service 直接查询 SQLite。
- 将来可增加独立的“全局聊天”工作区，但它不能与项目 Coding 会话共用默认历史。

## HTTP、事件与界面

- HTTP 路由归 `studio` 管理。路由函数只呈现：请求 JSON → `RunInput` → `Engine.Run` → `StreamEvent` → SSE。
- `engine` 包负责将 tRPC Agent Go 的 `*event.Event` 转换为稳定的应用 `StreamEvent`；HTTP 不读取框架 Event 字段。
- `frameworkEventCh` 只存在于 `Engine.Run` 内部，由当前 Run 同步消费。
- 除框架返回的 `frameworkEventCh` 外，不为 Event 翻译额外创建 channel、goroutine、缓存或事件桥。
- `StreamEvent.Type` 表达文本、思考、工具、错误等业务差异；禁止 `writeSSEText`、`writeSSETool`、`writeSSEStatus` 等按业务事件拆分的写入函数。
- HTTP 层只负责编码 HTTP/SSE；Next.js 只负责 UI，不理解框架内部 Event。
- Event 流的唯一完成判断是 `ev.IsRunnerCompletion()`。

## 框架与本地项目

- 优先使用 tRPC Agent Go 已有的 `tool/claudecode` 或 `tool/file`；不提前自研工具层。
- 暂不使用 CodeExecutor Workspace；它是框架的隔离执行能力，不等同于用户当前项目目录。
- 当前项目目录是产品概念 `ProjectRoot`：用户在哪个目录运行 `edith`，默认终端目录就是哪里。

## 变通条件

只有在并发安全、资源释放、安全边界或已出现的重复明确要求时，才能突破以上规则；并在代码注释中说明原因。
