# EDITH Studio：前端模块与本地接口

> 本文把已确认的三栏产品原型拆成前端功能模块和本地 Go API。
> 它不规定后端包如何实现；后端架构以 `architecture/架构设计.md` 为准。

## 1. 页面事实

一个 Studio 进程只对应一个 `ProjectRoot`。页面不提供切换项目的能力。

```text
┌──────────── Sessions ────────────┬──────────── Chat ─────────────┬──────── Files ────────┐
│ 当前目录的会话                    │ 对话、思考、工具卡片           │ 文件树 │ 代码 / Diff │
│ 扩展、设置                        │ 输入、模型、上下文、权限、附件 │                          │
└──────────────────────────────────┴───────────────────────────────┴──────────────────────────┘
```

页面级只保存跨栏事实：当前 `sessionId`、当前 `filePath`、已打开文件 Tab、当前 Run、当前模型和当前权限等级。其余状态留在各功能模块。

## 2. 前端模块

```text
web/src/
├─ app/                         页面壳与三栏布局
├─ api/                         本地 Go HTTP / SSE 调用
└─ features/
   ├─ sessions/                 当前项目的会话列表与历史选择
   ├─ chat/                     消息、思考块、工具卡片、SSE 事件归并
   ├─ composer/                 输入、/ 候选、附件、模型、上下文、权限
   ├─ files/                    文件树、文件 Tab、代码只读页、后续 Diff
   └─ runtime/                  当前 Run、分支、子 Agent、MCP 状态
```

`settings` 在真正有设置页面时才建立 feature；现在不预建空目录。

| 模块 | 负责的界面事实 | 需要的 API |
| --- | --- | --- |
| `sessions` | 当前目录会话摘要、选中的会话、历史加载 | Workspace、Sessions |
| `chat` | 当前会话消息块、SSE 事件如何更新卡片 | Session、Runs SSE |
| `composer` | 本次消息与 Run 选项 | Models、Runs |
| `files` | 展开的目录、当前文件、Tab、代码内容 | Files |
| `runtime` | 本次 Run 是否运行、未来子 Agent / MCP 状态 | Runs SSE、未来 Runtime |

## 3. 公共数据

所有字段使用 camelCase。Web 永远不接收项目绝对路径、框架 Event 或框架 Session 原始数据。

```ts
type Workspace = {
  projectName: string
  workspaceId: string
}

type ModelOption = {
  id: string
  label: string
  contextWindow: number
  maxOutputTokens: number
  input: { text: true; image: boolean }
  toolCalling: boolean
  reasoning: "none" | "toggle" | "effort"
  effortOptions?: string[]
}

type SessionSummary = {
  id: string
  title: string
  updatedAt: string
}

type FileEntry = {
  path: string
  name: string
  kind: "directory" | "file"
}

type FileContent = {
  path: string
  language: string
  content: string
  truncated: boolean
}
```

`workspaceId` 仅供前端稳定标识当前运行环境，不代表用户账号，也不允许前端自行指定。

## 4. HTTP 接口

### Workspace 与模型

```text
GET /api/workspace
→ Workspace

GET /api/models
→ { models: ModelOption[], defaultModelId: string }
```

页面启动时读取它们。模型 API 只返回已注册模型和它们的能力；不返回 API Key、Base URL 或 Provider 凭据。

### 会话

```text
GET    /api/sessions
→ { sessions: SessionSummary[] }

GET    /api/sessions/{sessionId}
→ { session: SessionSummary, messages: ChatMessage[] }

DELETE /api/sessions/{sessionId}
→ 204
```

点击“新建会话”只在浏览器生成新的 UUID 并切换空白聊天页。第一条 Run 持久化成功后，它才出现在 Session 列表。这避免伪造框架并不需要的空 Session 创建能力。

### 文件

```text
GET /api/files?path=<relative directory path>
→ { entries: FileEntry[] }

GET /api/files/content?path=<relative file path>
→ FileContent
```

`path` 始终相对 `ProjectRoot`。空字符串表示根目录。展开目录只读取直接子项；点击文件才读取内容。

### Run 与 SSE

```text
POST /api/runs
{
  requestId: string,
  sessionId: string,
  message: string,
  modelId?: string,
  reasoning?: { enabled?: boolean, effort?: string },
  permissionMode?: "strict" | "normal" | "unrestricted",
  attachments?: Attachment[]
}
→ text/event-stream StreamEvent

POST /api/runs/{requestId}/cancel
→ 204
```

第一版可先只实现既有的 `requestId`、`sessionId`、`message`；`modelId` 是紧接着需要补齐的真实 Run 选项。推理、权限与附件在对应能力完成前不发送、不伪造后端效果。

`Attachment` 只在文件上传功能实现后出现；它不能是无限制 Base64 字符串。

## 5. SSE 事件

`chat` 是唯一理解 `StreamEvent` 的前端模块。它按 `blockId` 或 `toolCallId` 更新当前 Assistant 消息；其他模块只读取已经归并后的显示状态。

```ts
type StreamEvent =
  | { type: "run.started" }
  | { type: "message.delta"; blockId: string; blockType: "text"; delta: string }
  | { type: "reasoning.delta"; blockId: string; blockType: "reasoning"; delta: string }
  | { type: "tool.requested" | "tool.started" | "tool.finished" | "tool.failed";
      toolCallId: string; toolName: string; arguments?: string; toolResult?: string }
  | { type: "run.completed" }
  | { type: "run.cancelled" }
  | { type: "run.error"; error: { message: string } }
```

`run.completed`、`run.cancelled`、`run.error` 结束当前页面 Run。浏览器网络断开只影响页面接收；后端仍完成该 Run 的 Session 收尾。

## 6. 交互边界

- 运行时：禁止发送下一条消息；保留停止按钮。
- 会话切换：首版在有 Run 时禁用切换和删除，避免把“后台 Run 归属”设计成隐含行为。
- 文件读取：文件树、代码页和 Agent Tool 都通过同一个 Go `project.Module` 看到本地文件。
- 模型选择：仅展示 `GET /api/models` 返回的模型；不把供应商参数写进页面。
- 上下文显示：没有可信 Token 统计前，显示“暂不可用”，不能展示硬编码百分比。
- 权限、附件、分支、子 Agent、MCP：原型中可展示位置，但在对应后端能力没有落地前必须标记为“即将支持”，不能假装可用。

## 7. 实施顺序

```text
三栏静态壳与就近类型
  → Workspace / Models / Sessions / Files 的读取接口
  → 前端接真实数据
  → Run 增加 modelId
  → 上下文、推理、附件、权限、MCP、Skills、子 Agent
```

这样每一步都由可见页面需求确定字段，而不是由后端先猜一个“大而全”的类型。
