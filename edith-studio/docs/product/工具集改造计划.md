# 本机工具层改造计划（方案 c + skill-creator 收尾）

> 目标：让 EDITH 的文件工具能访问全盘（含技能目录 `~/.edith`），bash 在 Windows 上不落 WSL。
> 本计划供子 Agent 直接执行，逐文件说明改动。

## 一、背景与目标

当前 EDITH 用框架的 `tool/claudecode` 工具集（见 `edith-studio/internal/tools/tools.go`）：

```go
toolSet, err := claudecode.NewToolSet(claudecode.WithBaseDir(projectRoot))
```

两个问题：
1. **B4**：文件工具（read/write/edit/glob/grep）被 `normalizePath` 锁死在 base_dir（项目目录），访问技能目录 `~/.edith/skills`、`~/.edith/.system-skills` 报 `path is outside base_dir`。模型无法读写技能文件。
2. **A1**：bash 工具硬编码 `"bash"`，Windows 上 PATH 里的 `bash` = WSL 启动器，导致乱码、路径两套、中文风险。

**决策：方案 c——本地持有 claudecode 包，做两处小改：放开 normalizePath（全盘访问）+ bash 平台分派（Windows 指 Git Bash）。** 对齐 Claude Code 的"工具全盘、项目为 cwd"语义。

## 二、前置事实（已确认）

- **依赖已就绪**：EDITH go.mod 已有 `doublestar`、`uuid`、`ledongthuc/pdf`、`go-pdf/fpdf`、`x/net`、`x/text`（都是 claudecode 的既有间接依赖）。copy 后**不需要加新依赖**。
- claudecode 只依赖框架**公开包** `trpc.group/trpc-go/trpc-agent-go/tool` 和 `.../tool/function`（EDITH 已依赖框架），**不依赖框架 internal 包** → 可整体 copy 到 EDITH 的 internal。
- bash 工具**本身不受 base_dir 限制**（baseDir 只作工作目录 cwd），改好 shell 后天然是全盘通道。

### 2. 改 `internal/claudecode/common.go`：放开 normalizePath（全盘访问）

当前 `normalizePath`（common.go 第 29-55 行）有两个越界检查要**删除**：

```go
// 删除这两个分支的 error 返回（约 6 行）：
// ① 绝对路径越界检查：
if rel == ".." || strings.HasPrefix(rel, ".."+string(filepath.Separator)) {
    return "", "", fmt.Errorf("path is outside base_dir: %s", raw)
}
// ② 相对路径 .. 检查：
if cleanPath == ".." || strings.HasPrefix(cleanPath, ".."+string(filepath.Separator)) {
    return "", "", fmt.Errorf("path is outside base_dir: %s", raw)
}
```

删除后函数形态：

```go
func normalizePath(baseDir string, raw string) (string, string, error) {
	pathValue := strings.TrimSpace(raw)
	if pathValue == "" {
		return "", "", fmt.Errorf("path is required")
	}
	cleanBase, err := filepath.Abs(baseDir)
	if err != nil {
		return "", "", err
	}
	if filepath.IsAbs(pathValue) {
		cleanPath := filepath.Clean(pathValue)
		// 绝对路径：全盘放行，不做越界检查
		return filepath.ToSlash(filepath.Clean(cleanPath)), cleanPath, nil
	}
	cleanPath := filepath.Clean(pathValue)
	absPath := filepath.Join(cleanBase, cleanPath)
	return filepath.ToSlash(filepath.Clean(cleanPath)), absPath, nil
}
```

**语义**：
- 绝对路径（`C:\...`、`/Users/...`）→ 全盘任意访问（模型可读写技能目录）
- 相对路径 → 基于 baseDir 解析，`..` 也允许（join 到 baseDir 外）
- **不需要**动 `filepath`、`strings` 的 import（它们还在用）

### 3. 改 `internal/claudecode/bash.go`：bash 平台分派（Windows 指 Git Bash）

当前两处硬编码 `"bash"`（bash.go 第 43 行前台、第 97 行后台）：

```go
runCapturedProcess(runCtx, runtime.currentBaseDir(), nil, "bash", "-lc", in.Command)  // 43 行
startProcess(runtime.currentBaseDir(), nil, outputFile, outputFile, "bash", "-lc", command)  // 97 行
```

把字面量 `"bash"` 换成新函数 `resolveShell()`。新增函数（放在 bash.go 内）：

```go
// resolveShell 返回 bash 可执行路径：Windows 上显式指 Git Bash（避免解析到 WSL 启动器），
// macOS/Linux 用系统 /bin/bash。
func resolveShell() string {
	if runtime.GOOS != "windows" {
		return "bash"
	}
	for _, p := range []string{
		`C:\Program Files\Git\bin\bash.exe`,
		`C:\Program Files (x86)\Git\bin\bash.exe`,
	} {
		if _, err := os.Stat(p); err == nil {
			return p
		}
	}
	return "bash" // 兜底：未装 Git Bash 时退回 PATH 解析
}
```

- **需要新增 import**：`runtime`（bash.go 当前没有）。
- `os` 已有 import（bashTimeout 用到）。
- `runCapturedProcess`/`startProcess` 内部用 `exec.LookPath(bin)`，传绝对路径时直接校验文件存在性，能正常通过。

## 五、风险与注意事项

1. **internal/claudecode 是私有拷贝**：以后框架 claudecode 升级，需要手动同步。当前 pinned v1.11.0，暂不考虑。计划书记录这个事实即可。
2. **normalizePath 放开是全盘访问**：模型可读写任意路径（对齐 Claude Code）。这是**有意的产品决策**（本地单用户）。系统 prompt "Work only in the current project" 是软约束。
3. **`..` 相对路径也放行**：`../` 相对 baseDir 的逃逸不再阻止。符合"全放开"。
4. **bash 兜底 `return "bash"`**：若用户机器没装 Git Bash，Windows 上仍会落 WSL。开发机已装 Git Bash（Claude Code 在用），验证不受影响。
5. **seed 测试同步**：`internal/skills/seed_test.go` 的 expected 文件清单若包含 skill-creator 的 `references/openai_yaml.md` 或 `agents/`，删除文件后要更新断言。
6. **E13（路径含空格）**：Windows 路径常含空格（`C:\Program Files\Git\...`），模型用 bash 传这类路径时引号易错。这是**使用方注意事项**，非代码改动——bash 工具描述里可提示"路径含空格时加引号"；自造 bash 用列表参数（`exec.Command(shell, "-lc", cmd)` 不拼接字符串）规避。随 A1（Git Bash 路径统一）部分改善。
7. **不要改 `reference/trpc-agent-go/`**：那是只读参考副本，改动不生效。所有改动在 `edith-studio/internal/`。
