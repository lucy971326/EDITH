# CopilotKit 前端库全景速查

> 写给"懂 React 但第一次接触 CopilotKit"的人。3 个包、6 个角色、每个 API 一句话。
>
> 信息来源：项目内已安装的 CopilotKit skills（`copilotkit-setup` / `copilotkit-develop` / `react-core` / `runtime` / `copilotkit-agui`）。

---

## 1. 一句话总结

**CopilotKit = "AI 时代的 UI 组件库"，只做一件事：让任何 Agent 都能快速接进 React UI。**

它负责三个不要让用户做的脏活：

```
  ① SSE 流式客户端（自动重连、流式渲染）
  ② 状态管理（消息列表、loading、cancel）
  ③ 工具调用卡片（不用自己画）
```

它**不**做：模型（你带 OpenAI/Anthropic key）、Agent 框架（你带 LangGraph / trpc-agent-go）、服务端存储（你接自己的 DB）。

## 3. 角色详解

### 角色 ① Provider 管家 — `<CopilotKit>`

```
<CopilotKit runtimeUrl="..." useSingleEndpoint>
  └─ 包住整棵树，所有子组件自动获得"对话上下文"
```

| 一句话 | 它是啥 |
|---|---|
| 总电箱 | 装修时装的总电箱——所有 hook 都从它取电（state / agent / messages） |
| 装在哪 | 在 `app/providers.tsx`（必须是 `"use client"`） |
| 必传 prop | `runtimeUrl`（后端地址） |

**最常用 props**：

| Prop | 干啥 |
|---|---|
| `runtimeUrl` | 后端 runtime 地址（必填） |
| `useSingleEndpoint` | `true`=所有请求走单端口；`false`=每个操作一个端口 |
| `headers` | 每个请求都带的 header（支持函数式拿动态 token） |
| `publicLicenseKey` | CopilotKit Intelligence 公开 key（**canonical**，旧名 `publicApiKey` 已弃用） |
| `showDevConsole` | 左下角调试弹窗 |
| `renderToolCalls` | 自定义工具调用 UI |
| `frontendTools` | 声明式注册前端工具 |
| `onError` | 全局错误回调 |

### 角色 ② Chat UI 组件

**3 个开箱即用的聊天框**——唯一区别是**位置**：

```
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ CopilotChat  │   │ CopilotSidebar│   │ CopilotPopup │
│              │   │              │   │              │
│ 占满整个房间 │   │ 贴右边抽屉   │   │ 右下浮窗     │
│ (最常用)     │   │              │   │              │
└──────────────┘   └──────────────┘   └──────────────┘
```

| 组件 | 何时用 |
|---|---|
| `CopilotChat` | 默认。聊天是你的主功能 |
| `CopilotSidebar` | 聊天是辅助功能，业务页是主功能 |
| `CopilotPopup` | 任何页面右上/右下角浮一个气泡 |

**坑**：v2 的 Chat 组件**全部来自 `@copilotkit/react-core/v2`**。
- ❌ `@copilotkit/react-ui`（v2 里只剩 CSS）
- ❌ `CopilotPanel`（**不存在**，常见幻觉）

### 角色 ③ Hooks — 真正干活的地方 🔥

按"想干啥"分 5 组：

#### 3.1 跟 Agent 打交道（情报组）

| Hook | 干啥 |
|---|---|
| `useAgent({ agentId })` | 拿 agent 实例，订阅消息/状态/run-status 变化 |
| `useAgentContext(...)` | **注册**全局 JSON 上下文（购物车、用户信息）给 agent 看 |
| `useCapabilities({ agentId })` | 问 agent "你能干啥"——用来 enable/disable 按钮 |

> 注：`useAgents()`（复数）**不存在**。要看 agent 列表，用 `copilotkit.subscribe({ onAgentsChanged })`。

#### 3.2 跟前端工具打交道（业务组）

| Hook | 干啥 |
|---|---|
| `useFrontendTool({...})` | 注册一个浏览器能干的工具（读 cookie、定位、剪贴板） |
| `useComponent({...})` | 注册一个 React 组件当工具用（`useFrontendTool` 的语法糖） |

#### 3.3 跟安全/确认打交道（路障组）

| Hook | 干啥 |
|---|---|
| `useHumanInTheLoop({...})` | 危险工具执行前弹确认框 |
| `useInterrupt({...})` | 处理 agent 中断事件（agent 主动问问题） |

> ⚠️ `useHumanInTheLoop` **必须**在 handler 里调 `respond(result)`（包括拒绝路径），否则 agent 永远挂着。

#### 3.4 跟 UI 渲染打交道（美工组）

| Hook | 干啥 |
|---|---|
| `useRenderTool({...})` | 给某个工具**单独**写卡片 UI |
| `useDefaultRenderTool()` | 一行兜底——所有未注册的工具统一用丑卡 |
| `useComponent({...})` | 渲染富组件到 chat（前端工具的场景） |
| `useRenderActivityMessage({...})` | 渲染"搜索中…/思考中…"这类活动消息 |
| `useRenderCustomMessages({...})` | 在指定消息前后插入自定义 UI |

> 注：`useRenderToolCall` **不是注册 hook**——它是 resolver，给自定义 chat 表面用。

#### 3.5 跟持久化/上下文打交道（数据库组）

| Hook | 干啥 |
|---|---|
| `useThreads({...})` | 列、改名、删 CopilotKit Intelligence 的会话 |
| `useAttachments({...})` | 文件/图片附件（拖拽、点击、粘贴） |
| `useSuggestions()` | 读当前建议列表 + 控制 reload/clear |
| `useConfigureSuggestions({...})` | 注册静态/动态建议按钮 |

> 注：`useThreads` 必须在 **Intelligence mode** 下用，否则报 `'Runtime URL is not configured'`。

### 角色 ④ Runtime 大脑 — `@copilotkit/runtime/v2`

**三本字典交给 CopilotRuntime**：

```ts
new CopilotRuntime({
  agents,         // Record<string, AbstractAgent>     ← 名册
  runner,         // AgentRunner                      ← 调度员
  intelligence,   // CopilotKitIntelligence (可选)    ← SaaS 模式开关
  mcpApps,        // MCP 中间件
  hooks,          // { onRequest, onBeforeHandler }   ← 鉴权/日志/限流
  transcription,  // 语音转文字服务
});
```

**3 个 runtime 类**：

| 类 | 模式 | 何时用 |
|---|---|---|
| `CopilotRuntime` | 兼容垫片 | 默认。自动选 SSE 或 Intelligence |
| `CopilotSseRuntime` | 显式 SSE | 内存线程、纯本地 |
| `CopilotIntelligenceRuntime` | Intelligence | 持久化线程、实时推送（**托管服务，不可自部署**） |

> ⚠️ **不能同时传** `runner` 和 `intelligence`——构造函数直接 reject。

**3 个 Runner**：

| Runner | 干啥 |
|---|---|
| `InMemoryAgentRunner` | 内存存线程。默认、demo、单实例 |
| `SqliteAgentRunner` | SQLite 存线程。**单实例持久化**（skill 提到） |
| `IntelligenceAgentRunner` | 接 CopilotKit Intelligence SaaS |

### 角色 ⑥ Endpoint 工厂

把 Runtime 挂到具体 HTTP 框架：

| 函数 | 框架 | 导入路径 |
|---|---|---|
| `createCopilotRuntimeHandler` | **任意 fetch 服务**（**canonical primitive**） | `@copilotkit/runtime/v2` |
| `createCopilotHonoHandler` | Hono / Next.js App Router | `@copilotkit/runtime/v2` |
| `createCopilotExpressHandler` | Express | `@copilotkit/runtime/v2/express` |

**两种路由风格**：

| 模式 | 路径 | 何时用 |
|---|---|---|
| **multi-route**（默认） | `/api/copilotkit/run`、`/connect`、`/stop`、`/info`、`/transcribe`、`/threads` | 默认 |
| **single-route** | 所有操作都 POST 到 `/api/copilotkit`，body 里写明 method | 接**只暴露一个端点**的后端（如 trpc-agent-go 的 `/agui`） |

> ⚠️ skill 强调：**避免**用 Hono/Express 适配器，**优先用** `createCopilotRuntimeHandler`（fetch 原生）。我们项目用 Hono 适配器是因为要配合 `HttpAgent` 转发到 Go 后端。

## 4. Hook 三层壳（心智模型）

```
<CopilotKit>                       ← ① Provider 壳（顶层管家）
   └─ <CopilotChat>                ← ② Chat 壳（聊天框 UI）
        └─ useFrontendTool(...)    ← ③ Hook 壳（在任何子组件里）
        └─ useAgent(...)
        └─ useHumanInTheLoop(...)
```

**铁律**：Hook 必须在 Provider 下，没 Provider 直接报错。

**App Router 注意**：Provider 必须 `"use client"`，但要放在**尽量外层**——不然下层拿不到 context。

## 6. 易踩的坑（一次记住）

| 坑 | 正确做法 |
|---|---|
| 从 `@copilotkit/react-core`（根）import `CopilotKit` | 从 `@copilotkit/react-core/v2` import |
| 用 `publicApiKey` | 用 `publicLicenseKey`（canonical） |
| 写 `<CopilotPanel>` | **不存在**。用 `CopilotChat` / `CopilotPopup` / `CopilotSidebar` |
| 调 `useAgents()` 拿 agent 列表 | 用 `copilotkit.subscribe({ onAgentsChanged })` |
| `useHumanInTheLoop` 没调 `respond()` | agent 永远挂着；reject 路径也要调 |
| `useThreads` 不在 Intelligence mode | 报 `'Runtime URL is not configured'` |
| 同时传 `runner` + `intelligence` | 构造函数 reject |
| 拿后端地址随便填 | `useSingleEndpoint` 必须跟后端模式一致（multi-route → false，single-route → true） |
| `useSingleEndpoint` 默认值反着记 | v1 兼容默认值是 `true`（单端点），配 multi-route 后端会 404 |
