# EDITH 前后端交互格式

> 新增或修改浏览器 ↔ BFF ↔ Go 的格式时，同时更新本文档及对应的 Go / TypeScript 类型。

## 请求

浏览器 → Next BFF：

```ts
type ChatRequest = {
  requestId: string; // 浏览器 crypto.randomUUID()，断线恢复与幂等键
  sessionId: string;
  message: string;
  imageIds: string[];
  uploadPaths: string[]; // 本次上传成功后由 Sandbox 返回的 uploads/ 相对路径
  modelId: string;
  reasoningOptionId?: string;
};
```

Next BFF → Go Runtime 的 Agent Gateway：

```ts
type GatewayMessageRequest = {
  requestId: string;
  userId: string;
  sessionId: string;
  message: string;
  imageIds: string[];
  uploadPaths: string[];
  modelId: string;
  reasoningOptionId?: string;
};
```

`userId` 只能由 BFF 从 Clerk 获取，浏览器不传。
Gateway 统一以流式模式执行，并向渠道适配器输出 `StreamEvent`。WebAdapter 将事件转为
SSE；未来 IMAdapter 在内部累计 `message.delta`，任务结束后只向 IM 平台发送最终纯文本。

WebAdapter 将 BFF 注入的 Clerk `userId`、浏览器 `sessionId` 与临时 `modelId` 构造成 Gateway 的 `IncomingMessage`。未来 IM Webhook 只传渠道名、平台用户标识与文本；Gateway 查询绑定表，并生成 `<channel>:<clerk_user_id>` Session ID。

同一个 `requestId` 只能启动一条 Agent Run。Web 使用 UUID；未来 IM 使用带渠道前缀的稳定平台事件 ID。Gateway 只要求非空，不强制 UUID 格式。

同一 `<userId, sessionId>` 在单个 Go Runtime 进程中同一时刻只能有一条活跃 Run。
Go 在启动 Run 前占位，并在事件流消费和资源收尾完成后释放；若该会话已有活跃 Run，
`POST /api/chat/stream` 返回 409。不同会话可以并行运行。

```text
GET /api/agent-runs/{requestId}
→ 200 { requestId: string, status: "running" }
→ 404 该 requestId 已不在 ManagedRunner 的活跃 Run 中

POST /api/agent-runs/{requestId}
→ 204 ManagedRunner 已接受取消信号
```

`GET /api/agent-runs/{requestId}` 和 `POST /api/agent-runs/{requestId}` 都由 BFF 从 Clerk 注入
`userId`。Go 使用 `ManagedRunner.RunStatus(requestId)` 查询活跃 Run，并校验其
`SessionKey.UserID`；不匹配和不存在统一返回 404，不泄露其他用户 Run 是否存在。

浏览器在发送前将 `{ requestId, sessionId }` 写入 sessionStorage。SSE 断线后轮询任务
状态：200 表示任务仍在后台执行；404 表示 Runner 已不再管理该 Run，此时重新请求
`GET /api/conversations/{sessionId}`，以完整 Timeline 恢复页面，再清除 pending 记录。
取消请求的 204 只表示信号已送达；浏览器同样必须等待查询变为 404，不能将 204 当作
任务已经结束。SSE 分片不做断点回放。

## 图片

图片是多模态消息输入，不进入 Sandbox。COS 仅存原始图片，SQLite 仅存图片元数据；浏览器和历史 Timeline 只保存 `imageId`。

```ts
type ChatImage = {
  id: string;
  mimeType: string;
};

type CreateImageUploadRequest = {
  sessionId: string;
  mimeType: "image/jpeg" | "image/png" | "image/webp";
  sizeBytes: number; // 单张最大 10 MiB
};

type CreateImageUploadResponse = {
  image: ChatImage;
  uploadUrl: string; // 短时 COS PUT URL，只用于本次直传
};
```

```text
POST /api/images                         ← CreateImageUploadRequest → CreateImageUploadResponse
POST /api/images/{imageId}/complete      → { image: ChatImage }
GET  /api/images/{imageId}               → 302 到新签发的短时 COS GET URL
```

`imageIds` 仅允许随支持 `capabilities.vision` 的模型发送。上传完成前，前端不得发送消息。

用户设置，浏览器 → Next BFF：

```ts
type SaveUserSettingsRequest = {
  personality: string;
  defaultModelId: string;
  providers: { providerId: string; apiKey?: string }[];
};

type UserSettingsResponse = {
  personality: string;
  defaultModelId: string;
  providers: { providerId: string; hasApiKey: boolean }[];
};
```

```text
GET /api/settings → UserSettingsResponse
PUT /api/settings ← SaveUserSettingsRequest → UserSettingsResponse
```

`apiKey` 只能浏览器 → 服务端；读取接口永远不返回明文 Key。
`defaultModelId` 是用户保存的默认模型，供 IM 与定时任务使用；Web 聊天页可临时覆盖它。
`timezone` 是用户所在 IANA 时区（如 Asia/Shanghai），定时任务按它解释 cron 表达式；创建任务时前端用浏览器时区自动带出，也可在设置界面修改。

## MCP 服务

```ts
type MCPTransport = "streamable" | "sse";

type MCPHeaderState = {
  name: string;
  hasValue: boolean;
};

type MCPServer = {
  id: string;
  name: string;
  url: string;
  transport: MCPTransport;
  enabled: boolean;
  headers: MCPHeaderState[];
};

type CreateMCPServerRequest = {
  name: string;
  url: string;
  transport: MCPTransport;
  enabled: boolean;
  headers: { name: string; value: string }[];
};

type UpdateMCPServerRequest = {
  name: string;
  url: string;
  transport: MCPTransport;
  enabled: boolean;
  headers: { name: string; value?: string }[];
};
```

```text
GET    /api/mcp-servers → { servers: MCPServer[] }
POST   /api/mcp-servers ← CreateMCPServerRequest → MCPServer
PUT    /api/mcp-servers/{serverId} ← UpdateMCPServerRequest → MCPServer
DELETE /api/mcp-servers/{serverId} → 204
```

Header 值只允许写入；读取接口仅返回 `hasValue`。

## 定时任务

```ts
type CronTaskType = "once" | "recurring";

type CronJob = {
  id: string;
  name: string;
  taskType: CronTaskType;
  schedule: string; // once: RFC3339 时间；recurring: 标准 5 段 cron 表达式
  prompt: string;
  enabled: boolean;
  nextRunAt: string | null; // RFC3339
  running: boolean;
  createdAt: string;
};

type CreateCronJobRequest = {
  name: string;
  taskType: CronTaskType;
  schedule: string;
  prompt: string;
  timezone: string; // IANA 时区，写入用户设置
};
```

一次性任务在表单中使用本地时间选择器（datetime-local），提交时由前端按浏览器时区自动转换为 RFC3339；周期任务仍填写标准 5 段 cron 表达式。

```text
GET    /api/cron-jobs → { jobs: CronJob[] }
POST   /api/cron-jobs ← CreateCronJobRequest → CronJob
PUT    /api/cron-jobs/{jobId} ← { name, taskType, schedule, prompt } → CronJob
DELETE /api/cron-jobs/{jobId} → 204
POST   /api/cron-jobs/{jobId} ← { enabled: boolean } → CronJob
```

调度器每 5 秒轮询；同一任务原子抢占防重叠。执行结果保存在 `cron:<jobId>` 会话中，不单独建执行记录表。

## Skills 列表

```ts
type SkillListItem = {
  name: string;
  description: string;
};

type SkillsResponse = {
  system: SkillListItem[];
  custom: SkillListItem[];
};
```

```text
GET /api/skills → SkillsResponse
```

公共 Skills 来自项目内置目录；用户 Skills 来自当前用户 Volume 的 `overview.md`。
浏览器不传 `userId`，Next BFF 从 Clerk 注入身份后转发给 Go Runtime。该接口只读摘要，
不返回 Volume 信息，也不读取完整 Skill 正文。

## Sandbox 文件面板

```ts
type SandboxFileEntry = {
  name: string;
  path: string; // 相对 /home/user；根目录为 "."
  type: "file" | "directory";
  size: number;
};

type SandboxFileTreeResponse = {
  path: string;
  entries: SandboxFileEntry[];
};

type SandboxFileContentResponse = {
  path: string;
  content: string;
  truncated: boolean;
};
```

```text
GET /api/sandbox/files?sessionId=...&path=...          → SandboxFileTreeResponse
GET /api/sandbox/files/content?sessionId=...&path=...  → SandboxFileContentResponse
POST /api/sandbox/files/upload?sessionId=...           ← multipart file → { path, name, size }
GET /api/sandbox/files/download?sessionId=...&path=... → attachment stream
```

浏览器不传 `userId`；Next BFF 从 Clerk 注入后转发给 Go Runtime，同时携带当前
`sessionId`。这两个接口只连接已经由 Agent 创建的 Sandbox：若该会话尚无 Sandbox，返回
`404 sandbox_not_found`，不得创建 Sandbox 或 Volume。`path` 只能为工作区相对路径，禁止
绝对路径和 `..`。文本预览最大 32 KiB；二进制、含 NUL 或非 UTF-8 内容返回
`422 file_not_previewable`，前端不应尝试展示正文。

普通文件在用户点击发送时才以 multipart 上传到当前会话 `uploads/`：单文件非空且不超过 50MB，BFF 从 Clerk 注入身份并流式转发。上传接口允许创建工作区；文件树、预览和下载只连接既有工作区。Go 只接受经 Sandbox 校验、当前用户当前会话 `uploads/` 内存在的 `uploadPaths`，再将其注入该次 Agent 指令。下载仅允许 `artifacts/` 普通文件；`uploads/`、`work/` 与 `skills/` 均不可下载。

## 历史与页面状态：Timeline

```ts
type Conversation = {
  id: string;
  title: string; // 第一条用户消息的前 18 个字符
  updatedAt: string;
};

type ConversationListResponse = {
  conversations: Conversation[];
};

type ConversationResponse = {
  timeline: Timeline;
  usage: SessionUsage;
};

type SessionUsage = {
  totalTokens: number;
  cachedPromptTokens: number | null;
  uncachedPromptTokens: number | null;
  completionTokens: number;
  cacheHitRate: number | null;
};
```

```text
GET /api/conversations → ConversationListResponse
GET /api/conversations/{sessionId} → ConversationResponse
```

```ts
type Timeline = {
  blocks: TimelineBlock[];
};

type TimelineBlock = UserBlock | AssistantBlock | ErrorBlock;

type UserBlock = {
  type: "user";
  id: string;
  content: string;
  images: { id: string }[];
  createdAt: string;
};

type AssistantBlock = {
  type: "assistant";
  id: string;
  createdAt: string;
  blocks: AssistantContentBlock[];
};

type ErrorBlock = {
  type: "error";
  id: string;
  message: string;
  createdAt: string;
};

type AssistantContentBlock = ReasoningBlock | TextBlock | ToolBlock;

type ReasoningBlock = {
  type: "reasoning";
  id: string;
  content: string;
};

type TextBlock = {
  type: "text";
  id: string;
  content: string;
};

type ToolBlock = {
  type: "tool";
  id: string;
  toolName: string;
  arguments: string;
  status: "running" | "completed" | "failed";
  result?: string;
};
```

`createdAt` 是 RFC3339 字符串。

## 实时 SSE

每个 `data:` 是 Gateway 的渠道无关事件之一。浏览器将它们投影为 Timeline；IM 或 GitHub 可投影为各自的卡片、消息或 Check Run。

```ts
type ChatStreamEvent =
  | RunStartedEvent
  | ContentDeltaEvent
  | ToolStartedEvent
  | ToolFinishedEvent
  | RunErrorEvent
  | RunCompletedEvent
  | RunCanceledEvent;

type RunStartedEvent = {
  type: "run.started";
  sessionId: string;
  requestId: string;
  assistantId: string;
};

type ContentDeltaEvent = {
  type: "reasoning.delta" | "message.delta";
  assistantId: string;
  blockId: string;
  blockType: "reasoning" | "text";
  delta: string;
};

type ToolStartedEvent = {
  type: "tool.started";
  assistantId: string;
  toolCallId: string;
  toolName: string;
  arguments?: string;
  toolStatus: "running";
};

type ToolFinishedEvent = {
  type: "tool.finished";
  assistantId: string;
  toolCallId: string;
  toolStatus: "completed" | "failed";
  toolResult?: string;
};

type RunErrorEvent = {
  type: "run.error";
  requestId: string;
  error: { type: string; message: string };
};

type RunCompletedEvent = {
  type: "run.completed";
  requestId: string;
  sessionUsage?: SessionUsage;
};

type RunCanceledEvent = {
  type: "run.canceled";
  requestId: string;
  sessionUsage?: SessionUsage;
};
```

## 工具配对

```text
ToolBlock.id = framework ToolCall.ID = tool.finished.toolCallId
```

收到 `tool.started` 创建卡片；收到 `tool.finished` 更新同一张卡片。不得按工具名配对。
