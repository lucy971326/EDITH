# EDITH 会话接力：当前项目全景与重要决策

> 给新会话的接手 AI / 开发者。目标是在不翻完整聊天记录的前提下，恢复 EDITH 的架构边界、
> 完成能力、关键取舍、当前代码地图与下一步。具体协议看 `05-格式约束.md`；框架与
> RunOptions 原则看 `01`、`02`；代码风格看 `04`。

---

## 1. 一句话定位

EDITH 是多用户、服务端优先的 Agent Runtime：**一个长期共享 Runner/Agent，用户差异按每次 Run 从 `userID` 加载，再以 RunOptions 和动态工具装配。**

当前入口是 Web Chat；未来可接 IM。Web 与 IM 都只是渠道，不应各自拥有一套 Agent 逻辑。

```text
Browser → Next.js BFF（Clerk 身份） → 私有 Go Runtime
        → trpc-agent-go Runner（模型、工具循环、Session、Event）
        → SSE → Browser Timeline
```

活跃目录：

```text
backend-v1/     当前 Go Runtime
web-v1/         当前 Next.js + Clerk BFF / UI
e2b-template/   EDITH 的 E2B Sandbox 模板源码
forward/        独立探索/验证；不是产品运行时
docs/AIKNOW/    接手 AI 的核心认知文档
reference/      框架 / SDK 本地参考源码和文档
```

**旧 `backend/`、`web/` 是 0.x 本地客户端式探索代码；不要据此推导或修改当前架构。**

## 2. 不能突破的边界

### 身份与信任

```text
浏览器：只发 sessionId、message、modelId、imageIds
Next BFF：从 Clerk 登录态得到 userId，再转给 Go
Go Runtime：只接受私有 BFF 请求；信任 userId，不解析 Clerk/JWT
```

- 浏览器绝不能提交 `userId`。
- Go 应只监听 loopback/私网，不能作为公网 API。
- BFF 管认证和对外 HTTP；Go 管 Agent、工具、模型、资源。

### 资源隔离键

| 资源 | 隔离键 | 当前归属 |
|---|---|---|
| Session / 对话历史 | `<appName, userID, sessionID>` | 框架 SQLite SessionService |
| Memory | `<appName, userID>` | 框架能力，尚未做产品层扩展 |
| 模型 Key、人格、MCP 配置 | `userID` | `internal/userconfig` |
| MCP 连接 | `userID + 本次 Run` | `internal/mcp` |
| E2B Sandbox | `userID + sessionID` | `internal/sandbox` |
| 图片 | `userID + sessionID + imageID` | `internal/images` + 私有 COS |
| Token 使用量 | `userID + sessionID + requestID` | `internal/usage` |
| Skills（未实现） | 至少 `userID` | 将来的 EDITH 自有系统 |

任何用户级资源必须从 `userID` 开始校验；会话资源再加 `sessionID`。

### 长期共享与本次 Run

```text
长期共享：Model adapters / LLMAgent / Runner / SQLite 服务 / E2B Client / COS Client
本次 Run：userID / sessionID / message / 用户配置 / requestID / API Key Header
          Prompt / MCP ToolSet / AdditionalTools / Usage 累计
```

禁止把“当前用户、当前 session、当前 API Key、当前 sandbox”塞进全局变量、共享 Agent 字段或长期 Server 字段。

## 3. 第一原则：用户差异都在 RunOptions 里

```text
错误：HTTP handler → New Agent(用户 key、prompt、tools) → Run
正确：HTTP handler → 读取用户配置 → Build RunOptions → shared Runner.Run
```

`backend-v1/internal/runopts/build.go` 是一次运行数据翻译成框架参数的唯一位置：

| RunOption | 来源 / 作用 |
|---|---|
| `WithRequestID` | Go 生成 UUID；框架 Invocation 的本次请求标识 |
| `WithStream(true)` | Web SSE 流式输出 |
| `WithModelName` | 浏览器选择、Go 校验后的服务端模型 ID |
| `WithModelRequestHeaders` | 用户 API Key，只进入本次模型 Header |
| `WithGlobalInstruction` | EDITH 身份 + 用户 personality |
| `WithInstruction` | 本次系统指令；未来可放 Skills 概览 |
| `WithAdditionalTools` | 本用户本 Run 的 MCP tools |

共享模型适配器不保存用户 API Key；共享 Agent 也不保存用户 Prompt。框架自动读取 Session 历史，因此不要把完整历史再塞进 `RunOptions.Messages`。

## 4. 当前 Agent Run 主链

```text
POST /api/chat/stream（浏览器）
  → BFF 从 Clerk 取得 userId
  → POST /internal/agent-runs（Go）
       1. 校验 modelId、图片能力
       2. 读取用户 API Key、personality、已启用 MCP
       3. 有 imageIds 时：校验归属并签本轮模型读取 URL
       4. 打开本 Run MCP ToolSet
       5. 创建 requestID，Build RunOptions
       6. shared Runner.Run(userID, sessionID, message, opts...)
       7. raw Event → timeline.Builder → SSE
       8. 累积完整模型响应的 Usage，写 agent_runs
       9. RunnerCompletion：发送 done + sessionUsage
      10. Run 返回后 Close MCP；异常时 usage 标 failed
```

- 整次 Run 只以 `rawEvent.IsRunnerCompletion()` 判断结束。
- `ctx` 是取消链：浏览器断连后应取消 BFF、Go、Runner、模型、MCP 与长耗时工具。
- MCP ToolSet 是本 Run 资源：**事件流消费完成后**才关闭，不能在加载函数返回前关闭。

## 5. 后端代码地图

```text
backend-v1/
├─ cmd/server/main.go         启动、.env、长期依赖组装、私有 HTTP Server
└─ internal/
   ├─ webapi/                 BFF 私有 API、运行编排、SSE
   ├─ userconfig/             用户模型凭据、personality、MCP 的 SQLite 配置
   ├─ models/                 支持模型唯一真相源
   ├─ runopts/                一次 Run 数据 → 七个框架 RunOptions
   ├─ mcp/                    用户远程 MCP → tools + cleanup
   ├─ tools/                  EDITH 默认工具注册和实现
   ├─ sandbox/                E2B 生命周期与 user/session 映射
   ├─ images/                 图片元数据、COS、消息/历史转换
   ├─ usage/                  agent_runs 与会话 Token 汇总
   └─ timeline/               framework Event → 前端 Timeline/SSE 协议
```

### `cmd/server/main.go`：唯一组装点

进程启动时只组装长期能力：

```text
userconfig.Store → 用户配置库
rawSessions → 框架 SQLite SessionService
images.Service → 图片元数据 + COS 私有访问
imageSessions → 对 SessionService 的图片读写包装
usage.Service → Token 运行账本
sandbox.Service → E2B client + sandbox 映射
tools.Default → 默认工具注册表
LLMAgent + Runner → 共享 Agent 运行骨架
webapi.Server → 注入上述能力并注册路由
```

`EDITH_DB_PATH` 默认 `edith.db`；`EDITH_ADDR` 默认 `127.0.0.1:8080`。`backend-v1/.env` 会被加载，外部环境变量优先。

### `webapi`：路由与 handler

`webapi.Server` 是长期能力集合，不是本次请求数据袋：`Runner / Users / Images / Sessions / Usage / AppName`。

`webapi.go` 只定义 `Server` 和 `Register`；具体 handler 放同包独立文件。路由注册时明确方法，例如：

```text
POST /internal/agent-runs
GET  /internal/models
GET  /internal/conversations/{sessionID}
POST /internal/images
```

不要在 handler 内以 `if r.Method` 处理方法分支。

### `userconfig`：配置读写，不承担功能实现

它统一存取用户的 provider API Key、personality、MCP server/header/enabled 与可用模型信息。

它不实现 MCP 连接、Sandbox、图片或未来 Skills。它的角色是“按 userID 读取配置”，不是把全部用户功能塞进一个包。

### `models`：模型唯一真相源

`Definitions []Definition` 是唯一需要人工新增模型的地方。每个定义绑定：

```text
Info（安全、浏览器可见的元信息）
  + Model（进程级共享 OpenAI-compatible adapter）
  + provider 例外能力
```

从它自动投影：`Catalog`（前端目录）、`Registered`（Runner 注册表）、`Lookup`（Run 时校验与能力查询）。

不要再手工维护 Catalog 或 Registered。模型 ID 是稳定运行键；Name 只是展示；ProviderID 表示读取该用户哪把 API Key。

能力是**模型级**而非供应商级。`capabilities.vision` 同时驱动前端图片按钮和 Go 的 `imageIds` 校验。

当前含 DeepSeek、MiniMax、StepFun（含 Step Plan）、小米 MiMo 等模型。某供应商 Usage 可能异常（StepFun Plan 已观察到），当前如实记录，不为单个兼容问题匆忙堆补丁。

### `mcp`：一 Run 一次远程连接

支持远程 HTTP MCP transport：`streamable`、`sse`。明确不支持 STDIO、本地 URL、下载/执行 server。

```text
LoadEnabledMCPServers(userID)
  → validateRemoteTarget（阻止 localhost、私网、link-local 等 SSRF 目标）
  → ToolSet.Init → ToolSet.Tools(ctx) → WithAdditionalTools
  → Run 完整结束后反序 Close ToolSets
```

`enabled` 表示该配置是否本次真正暴露给模型；关闭只是不加载，保留配置。Header 值只写不读：GET 仅返回 `hasValue`。

### `tools` 与 `sandbox`：能力和生命周期分开

`tools` 是“模型能调用什么”的默认工具注册表，`sandbox` 是“如何取得/恢复工作区”的长期服务。

```text
tools.Default(sandboxes)
  ├─ 无状态工具：get_current_time
  └─ SandboxToolSet：文件操作、命令/进程操作

Sandbox Tool ctx → agent.InvocationFromContext(ctx)
  → Invocation.Session.UserID + Session.ID
  → sandbox.OpenWorkspace(userID, sessionID)
  → Invocation State 缓存 *e2b.Sandbox（本 Run 复用）
```

Invocation 会跟随 ctx 进入深层 Tool 层，因此工具无需手工层层传 userID/sessionID。`*e2b.Sandbox` 是已连接 SDK 工作区句柄。

`user_sandboxes` 表记录 `<userID, sessionID> → sandboxID`。首次创建，后续 Connect；E2B 配置 `OnTimeout: pause` 与 `AutoResume: true`，闲置后自动 pause、下次使用自动恢复。

模板由 `EDITH_E2B_TEMPLATE` 指定。约定目录：`uploads/`（将来普通附件）、`work/`（处理过程）、`artifacts/`（面向用户的结果）。识图图片不进入 uploads，它是多模态 message 内容。

### `images`：私有 COS 图片

图片 bytes 不进 SQLite，存腾讯 COS 私有桶；`chat_images` 只存元数据、归属和 object key。

`images.Service` 的能力结构：

```text
db       元数据、user/session 归属校验
cos      COS 客户端能力接口
config   COS 身份与桶配置
```

`cosStore` 的关键小能力：

| 能力 | 用处 |
|---|---|
| `signPut` | 浏览器直传 COS 的短时 PUT URL |
| `signGet` | 浏览器或模型临时读取 COS 的短时 GET URL |
| `head` | 上传完成后校验对象存在、大小和 MIME |

完整图片链：

```text
浏览器选 JPEG/PNG/WebP（单张 ≤ 10 MiB）
  → CreateUpload：生成 imageId、写 pending、签 PUT URL
  → 浏览器直传 COS
  → CompleteUpload：Go HEAD 校验，改为 ready
  → ChatRequest 只发送 imageIds
  → Go 校验 user/session/ready，签本轮模型 GET URL，加入 model.Message
  → Session 持久化将临时 URL 替换为 edith-image://<imageId>
  → 历史重读将 edith-image://imageId 水合为新 GET URL
```

`object_key` 是 COS 的物理对象位置，例如 `chat-images/img_xxx`；`edith-image://img_xxx` 是 Session 历史的耐久逻辑引用。两者不能混用。

COS 虽私有读，签名 GET URL 仍可在公网访问，但仅在持有且未过期时。浏览器展示走 `/api/images/{imageId}`，BFF/Go 每次校验归属并 302 到新 URL；用户无需为 URL 过期手动刷新。

`images.WrapSessionService` 只是对框架 SessionService 的图片转换包装，不是重写 Session 实现；其它框架 Session API、未来 Summary 仍可使用。

### `timeline`：前端稳定投影

前端不直接理解 trpc-agent-go raw Event。`timeline.Builder` 投影为稳定协议：`assistant.started`、`assistant.content.delta`、`tool.started`、`tool.finished`、`error`、`done`。

Tool 卡片按 `ToolCall.ID` 配对，不能按工具名。实时 SSE 与历史 Session 都投影成同一个 `Timeline`；历史没有动画，但组件结构一致。

### `usage`：Token 账本

每个框架 Invocation 的 `requestID` 对应一条 `agent_runs`，不另造 run ID：

```text
Start(requestID, userID, sessionID, modelID) → running
完整模型响应 Usage 累积（绝不计 partial chunk）
RunnerCompletion → Complete → completed
中断或未完成 → Fail → failed
```

会话汇总只统计 completed Run：总 Token = prompt input + completion output；prompt input = 命中缓存 + 未命中缓存；缓存命中率 = 命中缓存 / prompt input。

前端当前仅展示会话总量和四项细分，不展示每条消息成本。缓存细项未报告时，应展示未知，不能前端硬算。

## 6. 前端与 BFF 地图

```text
web-v1/
├─ app/(authenticated)/chat/   Chat 页面入口（Clerk 守卫）
├─ app/api/                    BFF 路由：鉴权后代理 Go
├─ components/chat/            Timeline、composer、模型选择、Markdown
├─ components/settings/        账号弹窗中的 EDITH 设置内容
└─ lib/chat/type.ts            浏览器侧协议唯一 TypeScript 定义
```

### BFF 职责

- `auth()` 取得 Clerk `userId`；
- 向 Go 请求补充 `userId`；
- 转发 SSE，不自行实现 Agent Event 语义；
- 对图片、设置、MCP、会话 API 维持相同认证边界；
- 不在 BFF 管模型 API Key、MCP/E2B 生命周期或 Agent。

### 已完成 UI

- `/chat` 是正式子页面。
- 左侧固定会话栏，支持折叠；新会话由前端 UUID 生成 session ID。
- 会话标题默认第一条用户消息前 18 字符。
- Clerk 账户菜单与 EDITH 设置在左下角；不再依赖独立 Settings 页面。
- User / Assistant / Error 统一 Timeline；reasoning、tool card 默认折叠，浅灰统一视觉。
- `react-markdown + remark-gfm` 支持 Markdown 表格和代码块。
- Mermaid 客户端渲染；流式未完整时避免反复失败/闪烁，完成后稳定渲染。
- 长会话已做组件 memo 化，避免输入时重渲整条历史。
- Composer：Enter 发送、Shift+Enter 换行；自定义轻量模型选择卡，不使用原生丑下拉；Vision 为绿点/标签。
- Vision 模型才允许选图；上传中显示状态且禁止携图发送。
- Token 用量完全来自后端 `SessionUsage`，不在前端伪造统计。

视觉基调：浅白、浅灰、少装饰、无浓重 AI 味。好看必须复用组件语义，不能靠在 `chat-page.tsx` 堆一次性条件实现。

## 7. 存储与数据事实

EDITH 自己的配置、图片、Sandbox 映射和 Usage 服务共享一个 SQLite handle；框架
SessionService 因其 `Close()` 会关闭传入 DB，保留自己的 handle。两者都使用 WAL、5 秒
busy timeout 和单连接池，降低 SQLite 写锁竞争；各服务仍各自拥有自己的表。

| 表 / 存储 | 用途 |
|---|---|
| 框架 Session 表 | Session/Event/状态，由 trpc-agent-go SQLite Service 管理 |
| 用户配置表 | provider key、personality、MCP server、MCP headers |
| `user_sandboxes` | user/session 到 E2B sandboxID |
| `chat_images` | imageId、归属、COS object key、MIME、大小、状态 |
| `agent_runs` | requestID、用户/会话/模型、token、运行状态 |
| 腾讯 COS 私有桶 | 原始图片 bytes |
| E2B sandbox | 会话工作文件与进程环境 |

不得把 API Key、COS Secret、图片 bytes、临时签名 URL 返回到用户设置或 Session 事件中。

## 8. 明确不做的事

- 不为每用户创建或缓存 Agent / Runner；
- 不使用框架 CodeExecutor、Artifact、框架 Skills；
- 不允许 MCP STDIO、本地 URL、下载执行 server；
- 不让前端成为模型、设置、Token 等业务真相源；
- 不手动把 Session 历史重塞 `RunOptions.Messages`；
- 不为假想多云、多渠道预建大接口体系；
- 不因单个供应商异常立刻做复杂兼容补丁；
- 不把普通附件和识图图片混成一个功能。

## 9. 代码风格与协作约束

详见 `04-codestyle.md`。接手必须遵守：

1. 先区分长期能力和本次数据。
2. 纯数据用结构体字面量/`var`；`New/Open` 只用于真实初始化或资源取得。
3. 线性一次性流程优先函数，拒绝空壳 Manager/Builder/Factory。
4. 谁创建资源，谁在同一可读作用域负责关闭。
5. Go 代码要能从上到下顺读；不要炫技或隐式全局状态。
6. 新的 Browser ↔ BFF ↔ Go 格式必须同步更新 `05-格式约束.md` 与 Go/TS 类型。
7. 工作树可能有用户改动；只改任务范围，绝不 reset 覆盖无关文件。

## 11. 下一阶段：Skills 先于 IM

优先级已定：**先做 EDITH 自有 Skills，再做 IM 接入。**

Skills 是能力层；IM 是渠道适配。先把 Skills 做进 Runtime，未来 IM 只需把 IM user/session/message 映射到现有 Run。

已知前提：

- 不使用 trpc-agent-go Skills / Artifact；
- Skills 是用户私有资产，至少 `userID` 隔离；
- Skills 与 Sandbox 协作：可包含 Markdown、scripts、资源，最终在当前 session workspace 中使用；
- Skill 又必须跨 session 复用，因此不能只放在某个 session sandbox；
- 不把所有 Skill 正文每轮塞 Prompt；应先让模型看到紧凑目录/概览，再按需读取；
- 不要预设一定用 E2B Volume。先比较 COS 内容 + SQLite 元数据 + 按需读入 sandbox/tool 等方案，再定。

建议讨论/实施顺序：

```text
1. 定义 Skill：metadata、SKILL.md、scripts/resources、enabled
2. 定长期存放与用户隔离
3. 定 Agent 的发现与按需读取机制
4. 定文件如何进入当前 Sandbox 并运行
5. 契约优先：先写 05、前端设置 UI，再 BFF/Go CRUD
6. 最后接入 Prompt/工具/Sandbox
```

首版不要做 Skill 市场、版本发布、依赖解析、复杂权限或后台自动同步。

## 12. 新会话启动指令

```text
请先阅读：
1. AGENTS.md
2. docs/AIKNOW/01-trpc-agent-go-框架心智模型.md
3. docs/AIKNOW/02-EDITH-RunOptions-方针.md
4. docs/AIKNOW/04-codestyle.md
5. docs/AIKNOW/05-格式约束.md
6. docs/AIKNOW/06-会话接力.md

只看 backend-v1 与 web-v1，不看旧 backend/web。
先执行 git status，保留用户已有改动。
下一阶段先设计用户级、EDITH 自有、与 Sandbox 协作的 Skills 系统。
```
