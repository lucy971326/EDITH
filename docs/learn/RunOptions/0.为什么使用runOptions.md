# EDITH RunOptions 组装方案

> 一个 Runner + RunOptions = EDITH 服务端 Agent 的全部秘诀。

---

## 核心决定

**EDITH 只用一个 Runner**——所有渠道（Web / Telegram / 未来 Slack）共享。

**渠道差异 + 用户差异都在 RunOptions 里表达**——不拆 Runner。

---

## 三个维度

```
BuildRunOpts(channel, userCtx)
  │
  ├─ 1. 身份（每个 Run 必有）
  │    └─ RequestID
  │
  ├─ 2. 渠道默认（按渠道分类）
  │    ├─ web/sse      → WithStream(true)
  │    └─ telegram/im  → WithStream(false)
  │
  └─ 3. 用户个性化（按用户/上下文）
       ├─ Model     → WithModelName(ctx.Model)
       ├─ API Key   → WithModelRequestHeaders({Authorization: Bearer})
       └─ Skills    → WithGlobalInstruction(basePrompt + userSkills)
```

---

## 核心函数

```go
// forward/internal/runopts/build.go
func Build(channel string, ctx UserContext) []agent.RunOption {
    opts := []agent.RunOption{agent.WithRequestID(ctx.RequestID)}
    opts = append(opts, channelDefaults(channel)...)
    opts = append(opts, userOptions(ctx)...)
    return opts
}

func channelDefaults(channel string) []agent.RunOption {
    if channel == "web" || channel == "sse" {
        return []agent.RunOption{agent.WithStream(true)}
    }
    return []agent.RunOption{agent.WithStream(false)}  // telegram/slack/...
}

func userOptions(ctx UserContext) []agent.RunOption {
    var opts []agent.RunOption
    if ctx.Model != "" {
        opts = append(opts, agent.WithModelName(ctx.Model))
    }
    if ctx.APIKey != "" {
        opts = append(opts, agent.WithModelRequestHeaders(map[string]string{
            "Authorization": "Bearer " + ctx.APIKey,
        }))
    }
    if ctx.SkillsOverview != "" {
        opts = append(opts, agent.WithGlobalInstruction(
            basePrompt + "\n\n## 用户 Skills\n\n" + ctx.SkillsOverview,
        ))
    }
    return opts
}
```

**Web / Telegram handler 各调一行**：

```go
// web SSE：HTTP 请求和 Agent 任务使用不同的 ctx。
taskCtx, cancelTask := context.WithCancel(context.Background())
defer cancelTask()
runOpts := runopts.Build("web", userCtx)
eventCh, _ := r.Run(taskCtx, userID, sid, msg, runOpts...)

// telegram
runOpts := runopts.Build("telegram", userCtx)
eventCh, _ := r.Run(req.Context(), userID, sid, msg, runOpts...)
```

## 为什么 Stream 用 RunOptions 而不是 LLMAgent 字段

**两层 Stream 是两件事**：

| 层 | 字段 | 作用 |
|---|---|---|
| LLM 调用层 | `WithGenerationConfig({Stream: true})` | LLM API 是否流式 |
| Run 输出层 | `WithStream` | event 流是否分段 |

EDITH 默认 `Stream: true`（LLM 流式），RunOptions 的 `WithStream` 控制 event 流怎么传给 handler。

---

## EDITH 字段优先级

| 字段 | 用法 |
|---|---|
| `RequestID` | ✅ 链路追踪；由渠道入口生成后原样传入 |
| `WithStream` | ✅ 渠道默认 |
| `WithModelName` | ✅ 用户选模型 |
| `WithModelRequestHeaders` | ✅ **多租户关键** |
| `WithGlobalInstruction` | ✅ 用户 Skills 注入 |
| `WithAppName` | ❌ appName 固定 |
| `WithToolFilter` / `WithMaxRunDuration` | ⏳ 暂不用 |

---

## 一句话

> **一个 Runner + `runopts.Build(channel, userCtx)` = EDITH 所有渠道的入口**。
>
> 渠道默认 + 用户个性化——两个维度在一个函数里组合完毕。
