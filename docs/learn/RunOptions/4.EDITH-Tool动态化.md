# EDITH Tool 动态化

> EDITH 怎么用 RunOptions 字段做 Tool 层面的多用户差异化。

---

## 核心结论

| RunOptions 字段 | EDITH 用法 | 优先级 |
|---|---|---|
| **`AdditionalTools`** | ✅ **每次 Run 追加用户级 MCP 工具** | **核心** |
| `ToolFilter` | ❌ 暂不用 | — |
| `ExternalTools` | ❌ 暂不用 | — |
| `ToolExecutionFilter` | ❌ 暂不用 | — |
| `ToolPermissionPolicy` | ❌ 暂不用 | — |

---

## 为什么 AdditionalTools 是核心

**EDITH 真实需求**：用户可以在自己配置里加 MCP 工具，每次 Run 都要按用户拼装。

```
用户 A 的 MCP 配置:
  - GitHub MCP   (用户 A 自己的 token)
  - Slack MCP    (用户 A 自己的 workspace)

用户 B 的 MCP 配置:
  - GitLab MCP
  - Linear MCP

每次 Run:
  - 默认工具（time、memory_search）
  - + 用户 A 的 GitHub + Slack      ← AdditionalTools 追加
  - + 用户 B 的 GitLab + Linear    ← AdditionalTools 追加
```

---

## AdditionalTools 的语义

源码注释：

> "These tools are treated as user tools and are therefore affected by ToolFilter. They are appended to the effective tool surface **without mutating the agent's registered tools**."

**两个关键点**：
- **追加**——不影响 LLMAgent 长期配置
- **user tool**——受 ToolFilter 影响（EDITH 不传 ToolFilter 所以全部生效）

## EDITH 启动 + Run 流程

```
启动时:
  ┌──────────────────────────────────────────────────────┐
  │ llmAgent := llmagent.New("assistant",                │
  │     llmagent.WithToolSets(defaultToolSets),  ← 默认 │
  │     // 不在 AdditionalTools 范围                       │
  │ )                                                    │
  └──────────────────────────────────────────────────────┘

每次 Run:
  ┌──────────────────────────────────────────────────────┐
  │ runOpts := []agent.RunOption{                        │
  │     agent.WithRequestID(reqID),                      │
  │     agent.WithInstruction(skillsOverview),            │
  │     agent.WithAdditionalTools(                       │
  │         userMCPTools...,    ← 用户级 MCP 工具        │
  │     ),                                               │
  │ }                                                    │
  │ r.Run(ctx, userID, sessionID, msg, runOpts...)       │
  └──────────────────────────────────────────────────────┘
```

**关键**：`defaultToolSets` 在 LLMAgent 长期配置里，`userMCPTools` 在 RunOptions 里追加——**两层不冲突**。

## 其他 4 个字段为什么不用

### `ToolFilter`

**用法**：按角色过滤可见工具（管理员能看，普通用户不能看）。

**EDITH 现状**：没有角色概念，所有用户看到默认工具 + 自己的 MCP。

**结论**：不需要。

### `ExternalTools`

**用法**：暴露给模型但框架不执行（前端执行工具）。

**EDITH 现状**：所有工具都是后端执行，没有前端工具概念。

**结论**：不需要。

### `ToolExecutionFilter`

**用法**：过滤哪些工具调用实际执行（即使模型请求了，框架也不执行）。

**EDITH 现状**：用户级 MCP 工具已经通过 AdditionalTools 精确控制，没必要再二次过滤。

**结论**：不需要。

### `ToolPermissionPolicy`

**用法**：工具调用前审批（危险操作需用户确认）。

**EDITH 现状**：没有危险工具需要审批。

**结论**：不需要（未来若加"删除用户""封号"等工具再启用）。

---

## 用户级 MCP 工具的注入位置

**问题**：用户 MCP 工具从哪里读？

**两种方案**：

| 方案 | 位置 | 优点 | 缺点 |
|---|---|---|---|
| 启动时全部读 | LLMAgent.WithToolSets | 一次读反复用 | 不灵活 |
| **每次 Run 读** | **RunOptions.WithAdditionalTools** | **按用户动态** | **每次读慢** |

**EDITH 用方案 2**——因为每个用户的 MCP 配置都不同。

---

## 一句话

> **EDITH Tool 动态化 = `AdditionalTools` 每次 Run 追加用户级 MCP**。
>
> **其他 4 个字段 EDITH 暂不用**——等真实需求出现再启用。
