---

## 验证目标

> 同一个 EDITH Session 能否复用同一个 E2B Sandbox，并保留文件现场。

---

## 实验流程

```
Session 1 首次访问
    ↓
client.Create(timeout=5m, lifecycle={pause, auto_resume})
    ↓
写入测试文件 → 立即读取确认
    ↓
sbx.Pause() → 状态变为 paused
    ↓
Session 1 再次访问
    ↓
client.Connect(sandbox_id) → 自动恢复
    ↓
读取原文件 → 内容一致 ✅
    ↓
Session 2 首次访问
    ↓
client.Create → 不同 sandbox_id ✅
```

## 架构问题回答

> **Q: EDITH 是否只需保存 `session.Key → sandbox_id`，其余恢复和暂停交给 E2B？**

**A: 是。** 流程极简：

```
Session 首次访问 → client.Create → 保存 sandbox_id
Session 再次访问 → client.Connect(sandbox_id)
    ↓
E2B 自动处理：Pause、AutoResume、文件现场
```

EDITH 只需维护一个 `map[session.Key]string`。

### API 对应关系

| 操作 | Go SDK |
|------|--------|
| 创建（含 auto-resume） | `client.Create(ctx, CreateOptions{Timeout: ..., Lifecycle: &LifecycleOptions{OnTimeout: "pause", AutoResume: true}})` |
| 暂停 | `sbx.Pause(ctx)` |
| 连接/恢复 | `client.Connect(ctx, sandboxID, ConnectOptions{Timeout: ...})` |
| 文件写入 | `sbx.Files.WriteString(ctx, path, data, FsOptions{})` |
| 文件读取 | `sbx.Files.Read(ctx, path, FsOptions{})` |
| 查看状态 | `sbx.GetInfo(ctx)` → `info.State` |
| 清理 | `sbx.Kill(ctx)` |
