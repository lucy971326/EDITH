# EDITH AG-UI 统一历史验证实验报告

> **验证日期**: 2026-07-13
> **实验代码**: `forward/verify_agui/main.go`
> **运行命令**: `go run ./forward/verify_agui/main.go`

---

## 验证目标

**Web 与 GitHub 共用同一个 AG-UI Runner 时，AG-UI 历史能否统一展示。**

不验证真实 GitHub Webhook，只验证：两种入口产生的消息，最终是否进入同一套 AG-UI MessagesSnapshot 历史。

---

## 实验架构

```
                   共享 SessionService (inmemory)
                           │
                    sharedAGUIRunner (aguirunner.New)
                      ┌────┴────┐
                      │         │
                 sse.New()   直接调用 .Run()
                      │         │
                   Web SSE   GitHub Adapter
                 HTTP POST   (程序内调用)
```

**关键设计**：不使用 `agui.New()`，因为它内部会创建独立的 AG-UI Runner 实例。改为直接使用 `sse.New(sharedAGUIRunner)`，保证 Web 和 GitHub 共享同一个实例。

---

## 验证步骤

### 1. 搭建共享环境

```go
sessionService := inmemory.NewSessionService()
coreRunner := &fakeRunner{}

sharedAGUIRunner := aguirunner.New(
    coreRunner,
    aguirunner.WithSessionService(sessionService),
    aguirunner.WithAppName("edith"),
    aguirunner.WithUserIDResolver(func(...) (string, error) {
        return "test-user", nil
    }),
)

sseService := sse.New(sharedAGUIRunner,
    service.WithPath("/chat"),
    service.WithMessagesSnapshotEnabled(true),
    service.WithMessagesSnapshotPath("/history"),
)
```

### 2. Web Run — HTTP POST → SSE

发送：
```json
{"threadId":"github:test/repo#1","runId":"web-run-1","messages":[{"id":"msg-web","role":"user","content":"这是 Web 消息"}]}
```

> **注意**：AG-UI SDK 的 JSON 字段名是 camelCase（`threadId`、`runId`），不是 Go 风格的 `ThreadID`/`RunID`。

收到 5 个 SSE 事件：
```
RUN_STARTED → TEXT_MESSAGE_START → TEXT_MESSAGE_CONTENT → TEXT_MESSAGE_END → RUN_FINISHED
```

### 3. GitHub Run — 直接调用 sharedAGUIRunner.Run()

```go
events, err := sharedAGUIRunner.Run(ctx, &adapter.RunAgentInput{
    ThreadID: "github:test/repo#1",
    RunID:    "github-run-1",
    Messages: []types.Message{{
        ID: "msg-gh", Role: types.RoleUser, Content: "这是 GitHub 消息",
    }},
})
for range events {} // 必须消费完整事件通道
```

收到 5 个 AG-UI 事件（同上）。

### 4. 查询 MessagesSnapshot

POST `/history`：
```json
{"threadId":"github:test/repo#1","runId":"snapshot-check"}
```

### 5. 对照实验

用独立的 `SessionService` + 独立的 AG-UI Runner 执行一次 Run，验证原始 Session 不受影响。

## 验证结论

### ✅ 已验证的假设

1. **Web 和 GitHub 共享 AG-UI Runner 时，历史能统一展示** — MessagesSnapshot 包含两个来源的全部消息
2. **两种入口产生的 TrackEvents 都写入了同一个 Session** — 12 条 track events 在同一个 track 中
3. **共享 SessionService 是必要条件** — 独立 SessionService 互不干扰
4. **共享 AG-UI Runner 实例是必要条件** — `agui.New()` 内部会创建新实例，需改用 `sse.New(sharedRunner)`

### ⚠️ 注意事项

1. **AG-UI SDK JSON 字段是 camelCase** — `threadId` / `runId`，不是 `ThreadID` / `RunID`
2. **必须消费完事件通道** — 不消费完，Tracker Flush 不会完整执行，MessagesSnapshot 可能只看到部分数据
3. **`agui.New()` 和直接 `sse.New()` 的区别** — `agui.New()` 内部创建独立 AG-UI Runner；`sse.New()` 接受外部传入

### ❌ 本次未验证

1. **连续消息追加（EnqueueUserMessage）** — Session 运行中追加新消息，本实验只验证了串行 Run
2. **真实 Agent 下的 session_events 写入** — fakeRunner 不写 session_events
3. **Web 端 SSE 接收的完整体验** — 只验证了服务端事件流，没有前端 AG-UI 框架消费
4. **跨实例部署** — 未验证多进程/多机器下 Tracker 一致性

### 对 EDITH 现有代码的影响

现有 `main.go` 的代码：

```go
// 当前：使用 agui.New() → 内部创建独立 AG-UI Runner → GitHub 无法共享
aguiServer, _ := agui.New(coreRunner, agui.WithPath("/chat"), ...)

// 建议改为：
sharedAGUIRunner := aguirunner.New(coreRunner,
    aguirunner.WithSessionService(sessionService),
    aguirunner.WithAppName("edith"),
    aguirunner.WithUserIDResolver(...),
)

sseService := sse.New(sharedAGUIRunner,
    service.WithPath("/chat"),
    service.WithMessagesSnapshotEnabled(true),
    service.WithMessagesSnapshotPath("/history"),
)

// Web SSE 用 sseService
// GitHub Adapter 也调 sharedAGUIRunner.Run()
```

**无需修改框架代码。** 框架的 API 已经完整支持这种用法。

> **方案可行。Web 与 GitHub 共享 AG-UI Runner 时，AG-UI 历史能够统一展示。** 🎉
