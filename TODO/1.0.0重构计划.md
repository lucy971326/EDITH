# EDITH 1.0.0 重构计划

## 一句话定位

**多用户 Agent 服务端平台**。以 `user_id` 为隔离锚点，按需拼装每个用户专属的 Agent 运行时。

---

## 核心隔离维度

`Runner.Run(ctx, userID, sessionID, message)` — `userID` 是最大隔离单位。

| 维度 | 隔离键 | 生命周期 |
|---|---|---|
| Session | `<App, userID, sessionID>` | 单会话 |
| Memory | `<App, userID>` | 跨会话 |
| **Skills** | `userID` | 用户私有 |
| **MCP 工具** | `userID` | 用户私有 |
| **Model 配置** | `userID` | 用户私有 |
| Sandbox | `<userID, sessionID>` | 一会话一沙箱 |

公共系统配置与用户私有配置会合并:

```
每次 Runner.Run 拼装:
  Models    = 公共模型池 + 用户私有模型
  Skills    = 系统 Skills 概览 + 用户私有 Skills 概览
  MCP Tools = 用户私有 MCP 连接
  Sandbox   = 按 <userID, sessionID> 取得
  Memory    = 自动预加载用户长期记忆
```

所有"用户级 X"都是同一个模板 — 按 `userID` 加载、注入本次 Run、扩展时复制。

---

## 认证边界

| 层 | 负责 | 不负责 |
|---|---|---|
| **Next.js BFF** | Clerk 认证、Session、user_id 映射 | Agent、Tool、Sandbox |
| **Go 后端** | 业务、Agent、Skill、MCP、Sandbox | Clerk、JWT、OAuth |

Go 后端只认 `user_id` 字符串，不感知任何认证方式。

---

## "里面"和"外面"

```
里面（1.0 核心）:
  Runner.Run 的拼装逻辑
  用户级 Skills / MCP / Model / Sandbox 加载

外面（暂不处理）:
  Web / Telegram / 飞书 / Slack 等各种渠道入口
  只需往里面送 user_id + message
```
